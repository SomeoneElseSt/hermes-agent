Location Reminders

Proposed architecture — for sign-off. Hermes plugin · v0.2 draft

The idea

You tell the agent "remind me to buy microfiber cloths when I'm at Walgreens" and later, when you physically arrive there, Apple Reminders notifies you. You ask once, in chat.

The point of the design is what doesn't happen: your location is watched by iOS on your phone and never travels to the server. The agent never learns where you are.

What happens when you ask

  1. You ask for a reminder at a place.
  2. The agent looks the place up in your saved places, or takes the address you said literally.
  3. The plugin formats one line and posts it to your brrr webhook (outbound HTTPS only).
  4. brrr delivers it as a push notification. Your phone's automation fires on it — silently, even while locked — and the shortcut reads the line and creates the reminder with a location alert.
  5. Apple watches your location on-device and notifies you when you arrive.

Key concepts

Saved placeA name mapped to one address — walgreens → your Walgreens. Lives only in the plugin's data directory.
brrrA notification app: the plugin POSTs a line to a webhook and it arrives on your devices as a push. It stores the webhook secret and an APNs token, not your notification text. The secret is the owner's to look after — you export it wherever your Hermes runs.
Outbound-onlyNothing listens on your machine. No port, tunnel, domain or certificate is needed, because the phone never connects back to the server.
Trust boundaryThe server knows the places you plan to visit — it never knows where you actually are. That is the honest claim.

Commands

/add-place walgreensSave a place. Opens a form asking for the address; the address is saved to the mapping and the agent is told only "saved".
/edit-place walgreens 135 Powell StChange a saved place's address.
/placesList saved places.
/remove-place walgreensForget a saved place.

The agent can do the same four things when you ask it to in chat — it has save_place, edit_place, list_places and remove_place alongside the reminder tools. The difference is privacy, not capability: with the slash command the address never reaches the agent, while an edit you ask for in chat puts it in the conversation. Use the command when the address itself is sensitive, chat when it's just convenient.

Tools the agent gets

add_reminder(place, text)   # place = saved alias or literal address
list_reminders()            # what's been sent / delivered
cancel_reminder(id)

save_place(name, address)   # same effect as /add-place, but the
edit_place(name, address)   # address passes through the chat
list_places()              # names + a redacted address tail only
remove_place(name)

list_places() never returns a full address to the agent. Each saved place comes back as its name plus a redacted tail — walgreens → …Powell St (San Francisco) — so the agent can tell two entries apart without holding your addresses. /places, run by you, prints them in full.

What the agent never sees

  • Your location, at any point — no GPS fix, no arrival event.
  • Addresses you type into /add-place — it only learns that a place was saved. (If you ask it to save a place in chat instead, the address is in the conversation by definition.)
  • Anything the phone resolves on its own; Apple Maps fills in the real coordinates.

Known limits

  • Setup is a few taps. One shared shortcut, then one notification automation you create by hand — automations can't be shared or imported from a link. The brrr webhook lives on the agent's machine, so the user never installs it.
  • Geofencing is approximate. Radius is in the hundreds of metres, a pin can be off by up to a kilometre when a place is resolved from text, and a reminder made while you're already inside the area won't fire until you leave and return.
  • Shared region budget. Reminders monitors about 20 regions per device, shared with other apps, so very old location reminders can silently stop firing.
  • The notification automation is not on Apple's silent-run list. It was verified working on a locked iPhone (iOS 27.2.1), but Apple doesn't guarantee it, so a future iOS update could start asking for a tap.
  • Push content is not end-to-end encrypted. Apple's guidance is not to put sensitive data in a notification; we send a place name and reminder text, never your location.

Verified so far

  • brrr delivers a push from the VM: {"success":true}, HTTP 202.
  • A notification automation filtered on the title ran by itself, twice, on a locked iPhone.
  • Shortcuts' Add New Reminder exposes location alerts with any address Apple Maps can find.

A note on onboarding

On iOS 27, Apple Intelligence in Reminders can build a reminder — including its location — from a plain sentence. Where the device supports it, the agent hands the user one prompt to paste in, and Reminders fills in the details itself. It is an optional faster path, offered only when the iPhone supports Apple Intelligence; the shortcut and automation remain the default and still do the work for older phones and for anything created while the phone is locked.
